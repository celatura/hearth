## 3. 已知问题（均为有意取舍）

1. **成功页刷新丢失**：订单成功态保存在组件内存中，刷新后回到空购物车守卫页（购物车已按预期清空）。演示正常路径不受影响。
2. **数据为客户端模拟**：无真实后端；"网络失败重试"需借助 DevTools 断网模拟（retry: 1 后展示重试面板）。
3. **图片体积**：商品图为 1024px PNG（约 1MB/张），本地演示无感；生产环境应转 WebP/AVIF 或由图片 CDN 优化。
4. **仅浅色主题**：暖色画廊是品牌身份的一部分，未实现深色模式。
5. **搜索叠加语义**：搜索与分类是叠加过滤（URL 同时保留 `q` 与 `category`），与主流电商一致；如需"搜索时忽略分类"可调整 `parseFilters` 的一行逻辑。

## 4. 主要取舍

| 决策 | 理由 |
| --- | --- |
| 客户端 mock API 替代真实后端 | 保留异步/缓存/重试语义；`lib/api.ts` 一文件即可切换真实 HTTP |
| 结账纯前端模拟 | 题目明确无需真实支付；保留完整校验链路展示正确性 |
| URL 作为筛选事实来源 | 可分享、可前进后退、零额外状态同步成本 |
| `useSuspenseQuery` + 分层 Suspense | 首屏整页骨架；筛选变化只换结果区，工具栏保持可交互 |
| Zustand 存购物车（而非 Query 缓存） | 跨路由共享 + localStorage 持久化，语义最贴切 |
| 陶土色仅作"注意力信号" | 促销价/Sale/角标/进度/焦点环；星评与正文保持炭色，避免色彩噪音 |
| 不引入测试框架与 CI | 时间预算内，agent-browser 实机全流程 + 截图是收益最高的验证 |

## 5. 录屏脚本（约 90 秒）

1. **开场（0:00）**：打开首页——Hero 大标题与两幅商品静物入场，缓慢下滑展示 12 件商品网格。
2. **查找（0:15）**：在顶部搜索框输入 `lamp`——停顿展示防抖与"1 piece matching 'lamp'"；清空后点击 `Lighting` 分类 chips；打开排序选 `Price: low to high`，指出 $59 的 Dusk Wall Sconce 置顶。
3. **详情（0:35）**：进入 **Fjord Wool Rug**——指出 Sale 徽标、划线原价 $189、`Save $40.00`、`Only 6 left`；数量调到 2。
4. **购物车（0:50）**：点击 Add to cart——toast 出现、头部角标变 2；打开购物车抽屉，指出"Free shipping unlocked"进度条；演示加减数量与删除。
5. **结账（1:05）**：点击 Checkout——先直接点 `Place demo order` 展示三处表单校验；再填写姓名/邮箱/地址，提交，展示 800ms loading → 成功页订单号与"no payment"提示，购物车已清空。
6. **持久化（1:25）**：回到列表加购一件，**刷新页面**——角标与购物车内容仍在（localStorage）。
7. **移动端（1:35）**：切到 390 宽视口——吸底搜索行、2 列网格、抽屉全宽；结束。

> 备选加分镜头：直接访问 `/products/not-a-real-id` 展示 404；`bun run build` 终端输出展示 18 个静态页。
